# 微信全体通知汇总 · AstrBot 插件

**一个插件完成本机微信读取、群通知整理和每日早报。**

v2.0 内置 Windows 微信读取模块，无需单独安装或打开 WeChatDataAnalysis。自动识别群里的真正 `@全体成员` 通知，整理成“来自哪个群、要做什么、何时截止、准备什么材料”，再通过机器人私聊查看或定时接收。

> 内置读取已在 **Windows x64 + Python 3.12 + 微信 4.1.15.55** 验证。AstrBot 与桌面微信需在同一台电脑运行。其他微信版本尚未经实测。
>
> 为兼容旧配置，默认数据源仍是 `external`。**新用户使用内置读取，请先按下面步骤选择 `builtin`。**

## 功能

| 功能 | 说明 |
| --- | --- |
| 内置微信读取 | 插件管理后台读取进程，不需要另开采集软件 |
| 自动收集 | 默认每60秒扫描，去重保存群内结构化 `@全体成员` 通知 |
| 清晰汇总 | 群名、具体待办、截止时间分别展示 |
| 截止排序 | 临近截止的优先，明确催办的提前，已过期事项末尾单列 |
| 材料清单 | 列出通知明确要求的材料、份数或格式，不自行猜测 |
| 屏蔽群 | 支持完整群名或群ID，重启后继续有效 |
| 每日早报 | 可设置北京时间07:00私聊发送；无新增不打扰 |
| 断点恢复 | 保存采集进度及早报发送记录，失败后继续重试 |

汇总示例：

```text
①【班级群】🔴 今天截止
要做：提交助学金申请。
截止：10月20日 17:00
材料：申请表、身份证复印件、家庭情况证明。

②【课程群】🟠 3天内截止
要做：完成课程选题登记。
截止：10月22日
```

群名由程序根据实际来源填写。未说明截止时间则写“未注明”；没有材料要求就不增加材料行。模型无法完成总结时会明确提示并回退通知原文。

## 安装与首次初始化

### 1. 安装插件

在 AstrBot 插件管理中使用本仓库地址安装：

```text
https://github.com/yudanpi/astrbot_plugin_wechat_notice_digest
```

也可以通过 GitHub 的 **Code → Download ZIP** 下载源码包，在 AstrBot 中上传安装，或把插件放入 `data/plugins/astrbot_plugin_wechat_notice_digest`。

最低 AstrBot 版本为 **4.29.0**。安装 Python 依赖需要联网，内置读取使用 Frida、PyCryptodome、zstandard 和 psutil；这些依赖不等于另装一个桌面采集软件。

### 2. 找到微信数据库目录

在微信设置中确认文件保存位置，找到当前账号的 `db_storage` 文件夹。例如：

```text
D:\xwechat_files\wxid_example_ab12\db_storage
```

这里的 `wxid_example_ab12` 只是示例。请使用自己电脑上的实际目录名。

### 3. 配置内置读取

在 AstrBot 的本插件配置中填写：

| 配置项 | 填写内容 |
| --- | --- |
| `source_mode` | `builtin` |
| `wechat_storage_dir` | `db_storage` 的完整路径 |
| `account` | `db_storage` 上一级账号目录名，例如 `wxid_example_ab12` |
| `reader_initialize` | 首次设为开启，然后重载插件 |

重载后，在 **120秒内从托盘完全退出微信，再从桌面重新打开并正常登录**。仅关闭聊天窗口不算退出。插件不会强制结束微信，初始化开关会自动复位。

初始化完成后，在机器人私聊发送 `/通知状态`，检查“插件内置读取”、初始化状态和最近扫描时间。后续无需重复初始化，保持微信和 AstrBot 运行即可。

读取凭据失效、微信升级或权限不一致时可能需要重新初始化。账号必须明确绑定，不会自动跟随微信切换到另一个账号；多账号请使用独立实例及数据目录。

## 私聊指令

| 指令 | 功能 |
| --- | --- |
| `/通知状态` | 查看数据源、初始化状态、扫描时间、积压和早报状态 |
| `/通知汇总` | 汇总最近24小时已采集的通知 |
| `/通知汇总 3` | 汇总最近3天，支持1–30天 |
| `/通知原文` | 查看最近10条已采集通知原文 |
| `/屏蔽群 群名` | 停止采集该群，并隐藏其已保存通知 |
| `/取消屏蔽群 群名` | 恢复采集与展示 |
| `/屏蔽列表` | 查看已屏蔽群及群ID |

所有指令仅限私聊，但**目前没有管理员限制**：任何能私聊机器人的用户都能查看汇总、修改整个实例的屏蔽列表。请按自己的使用范围配置机器人访问权限。

群名必须完整匹配。同名群或名称包含连续空白时，请使用以 `@chatroom` 结尾的群ID。屏蔽记录持久保存，取消屏蔽后原有通知恢复展示；已经发送的内容无法撤回。若更改了 AstrBot 唤醒前缀，指令也使用对应前缀。

## 设置每天早上07:00汇报

| 配置项 | 示例 |
| --- | --- |
| `daily_report_enabled` | `true` |
| `daily_report_time` | `07:00` |
| `daily_report_target` | 私聊发送 `/sid` 后得到的完整 UMO |

时间使用北京时间、24小时制。目标必须是私聊 `FriendMessage` 的 UMO。**发布包默认关闭早报，目标留空，不包含个人账号。**

早报只包含尚未汇报且未屏蔽的通知；没有新增时不发。手动汇总不影响早报发送记录。成功发送的分段会保存进度，失败15分钟后从失败段重试；少数网络确认丢失的情况可能出现重复段。

电脑需要开机，微信已登录，AstrBot持续运行。已启用后错过时间会在恢复后补发一次；首次启用或修改目标/时间，会安排下一个未来时刻。个人微信主动消息的会话凭据失效时，可先私聊机器人再等待重试。

## 截止时间与材料规则

排序依次为：**今天截止 → 未来三天截止 → 无日期但明确催办 → 其他明确日期 → 普通无日期 → 已过期事项**。同一日期档内按截止时刻排序，同一时刻明确催办者优先。

相对日期根据通知原始时间推算；只有日期没有时间时，按当天结束判断是否过期。无法确定的期限保留原话，不编造日期。已过期不代表已完成，仍需自行确认是否补办。

材料清单只提取通知或相关上下文中明确写出的要求，不猜测未读取附件里的内容；材料要求不同的事项不直接合并。日期和要点由模型提取，重要事项请核对原文。

## 采集范围与升级

- 默认扫描所绑定账号可读取的全部群，可用 `group_ids` 限定范围。默认每60秒扫描，最低30秒；每群每轮最多10页、每页100条，超出部分下一轮继续。
- 只认结构化提及字段中的 `notify@all`。普通聊天正文出现“@所有人”不会被当作全体通知。
- 通知等待至少60秒再纳入汇总；关联同一发送者前后5分钟内、各最多3条候选补充，模型需判断其是否与通知相关。
- 已采集通知保留30天。`/通知汇总 30` 查询的是已保存记录，不等于首次安装就回填30天历史。
- 切换内置/外部数据源时，保留原通知、群屏蔽及发送记录，并清除旧传输的分页状态。为避免不同来源的历史ID重复，**只采切换所在整秒之后的新通知**，边界这一秒不回填，旧历史仍可查询。首次切换到内置读取也遵循这一规则。
- 外部模式首次采集回看最近24小时；后续增量读取。电脑未同步、已删除或停机期间无法恢复的数据不保证完整。

通知与进度保存在：

```text
data/plugin_data/astrbot_plugin_wechat_notice_digest/notices.db
```

## 数据处理与模型调用

内置读取只读访问微信数据库及WAL，明文快照仅在读取进程内存中查询，不创建全量明文镜像。读取凭据以Windows当前用户DPAPI保护，不通过私聊、配置JSON、日志或模型传递。只有本机配置能开启初始化。

自动采集不调用模型。**手动汇总和定时早报会把被选中的通知及相关候选补充发送给 AstrBot 当前会话配置的模型服务商。** 屏蔽群不会纳入新请求；已发给模型或微信的内容无法撤回。附件仅使用消息提供的名称/文字，不读取附件正文。

每次默认最多40条通知，最多可配置100条；模型总输入最多30000字符。正文、上下文过长或通知未被纳入时会明确提示。早报未展示的记录继续等待，模型不可用时退回本次范围内的原文。

不要把个人配置、读取凭据、运行数据库或聊天记录放进源码仓库、插件ZIP或发给其他人。

## 可选：使用外部采集工具

旧版本用户仍可选择 `source_mode=external`，通过本机HTTP接口连接 WeChatDataAnalysis：

- [WeChatDataAnalysis GitHub 项目](https://github.com/LifeArchiveProject/WeChatDataAnalysis)
- [安装包下载](https://github.com/LifeArchiveProject/WeChatDataAnalysis/releases/latest)

按原项目说明加载账号并确认实时读取正常，保持该工具运行。`api_url` 默认 `http://127.0.0.1:10392`，只接受本机HTTP地址，不跟随重定向。接口需提供账号、会话和消息查询，以及实时来源、稳定消息ID和结构化提及信息。

**内置模式不需要安装此工具。**

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 内置读取未初始化 | 检查账号目录名、`db_storage` 路径，开启一次性初始化并按提示重启微信 |
| 微信未登录所绑定账号或权限不一致 | 登录所选账号，确认AstrBot和微信运行权限一致；不会自动切换账号或提权 |
| 读取进程不可用 | 检查Python3.12和依赖安装，查看插件日志后重载 |
| 微信升级后失败 | 可能出现版本或数据库格式变化；当前只验证4.1.15.55，可暂时回退外部模式 |
| 通知为零 | 确认初始化、最近扫描及群范围；正文里的“@全体成员”不一定是结构化提及 |
| 早报没收到 | 查看 `/通知状态`，确认目标UMO、电脑运行状态和是否有新增通知 |

状态显示失败、积压、离线或过期时，汇总会提示覆盖限制；采集失败不推进相应游标。群列表达到2000会话上限会提示不完整。插件不会配置电脑开机自启。

## 开发与验证

在Windows上安装AstrBot和本插件依赖后，从插件目录运行：

```powershell
python -m unittest discover -s tests -v
```

当前82项测试覆盖合成加密数据库、WAL事务、消息归一化、账号隔离、初始化、进程协议恢复、群屏蔽、汇总排序及早报。自动测试不读取真实微信聊天、不发送真实测试消息。另已完成微信4.1.15.55的本机初始化和直接读取验证。
