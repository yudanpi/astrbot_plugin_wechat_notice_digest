# 微信全体通知汇总

AstrBot 插件：读取本机 WeChatDataAnalysis 的群聊数据，筛选真正的 `@所有人` 通知，自动去重保存，再在私聊中查询原文或 AI 要点列表。

## v2.0 内置读取（Windows验证中）

只安装本插件即可启用内置读取，无需独立安装或打开WeChatDataAnalysis。第一版要求 Windows x64、Python3.12、桌面微信与AstrBot同机。具体微信版本必须实测；当前开发目标为4.1.15.55，未经实测的版本不承诺兼容。

首次操作：
1. 安装插件及其Python依赖；首次下载Frida等依赖仍需联网。
2. 在微信设置中确认数据保存位置，找到该账号的 `db_storage` 目录。
3. 插件配置 `source_mode` 选择 `builtin`；`wechat_storage_dir` 填该目录的完整路径，`account` 填它的上一级目录名。不能跨账号共用数据。
4. 开启一次性 `reader_initialize` 并重载插件；120秒内手动退出、从桌面打开微信并正常登录。开关会自动复位，不会反复触发初始化，也不会由插件强制结束微信。
5. `/通知状态` 查看初始化与最近扫描；确认内置采集正常后可关闭外部采集工具。后续只需微信与AstrBot持续运行。

凭据只在本机使用Windows当前用户DPAPI保护，不通过私聊、日志或模型传递。普通聊天无法开启初始化。数据库与WAL只读，明文快照仅在读取进程内存中使用，不创建全量明文镜像。凭据失效、微信更新或权限不一致时会暂停并提示；按需手动重新初始化。

为保护旧用户，配置默认仍为 `external`，不会自动替换正在使用的数据源。切换数据源时保留已有通知、屏蔽与早报记录；为避免不同来源历史ID不一致导致重复，默认只采切换后的新通知，旧历史仍可查询。切回external也采用同样边界。变更账号请使用独立AstrBot实例/插件数据目录。

## 使用

1. 保持电脑微信、WeChatDataAnalysis 和 AstrBot 运行。确认数据分析工具已完成账号加载、实时读取正常，本地接口默认是 `http://127.0.0.1:10392`。
2. 在 AstrBot 安装本插件 ZIP，或将插件目录放入 `data/plugins/astrbot_plugin_wechat_notice_digest` 后重启 AstrBot。
3. v1.0.1 起按用户要求移除管理员限制，无需设置管理员；任何能私聊该机器人的人都可查询已采集的群通知。群聊调用仍被拒绝。
4. 等待首次扫描完成，在机器人私聊发送：

| 指令 | 功能 |
|---|---|
| `/通知状态` | 查看连接、扫描时间、群数、积压、通知数量 |
| `/通知原文` | 最近 10 条已采集全体通知及群来源、时间 |
| `/通知汇总` | 最近 24 小时的通知要点 |
| `/通知汇总 3` | 最近 3 天的通知，支持 1–30 天 |
| `/屏蔽群 群名` | 不再采集该群，同时隐藏其已保存通知 |
| `/取消屏蔽群 群名` | 恢复该群的采集和展示 |
| `/屏蔽列表` | 查看已屏蔽群及其稳定群 ID |

若修改了 AstrBot 唤醒前缀，请使用新的前缀。所有指令均仅私聊可用。默认不主动发消息；配置每日早报后会定时私聊发送。

## v1.1.0：简洁汇总与屏蔽群

汇总固定为纯文本三行卡片，群名由程序根据真实消息来源填写，不让模型编造：

```text
①【班级群】
要做：完成停保，并提交截图。
截止：10月18日 12:00

②【课程群】
要做：填写报名表。
截止：未注明
```

不再附长串来源索引。明确的相对日期由模型根据通知原始时间解析；模糊期限保留原话，完全没有截止要求时显示“未注明”。模型返回不合规数据时会明确说明总结未完成并回退原文。

屏蔽命令支持完整群名（含空格）或以 `@chatroom` 结尾的群 ID；不做模糊匹配，避免屏蔽错群。同名时会列出群 ID，指定 ID 后重试。群名来自最近扫描到的群列表，初次更新后需等待首次扫描完成。

微信指令解析器会压缩连续空白；群名包含多个连续空格等特殊空白时，请改用群 ID。

屏蔽列表保存在插件 SQLite 中，重载、重启后仍有效；屏蔽对整个插件实例生效，任何能私聊机器人的用户都可以修改。已保存的通知只是隐藏，不会删除；取消屏蔽后重新显示，后续会补采保留期内可读取的记录。每次模型请求前重新检查屏蔽列表；混合了屏蔽群内容的摘要整条弃用，不改挂到其他群名下。分段发送期间屏蔽设置变化时停止剩余发送，请重新查询；已经发给模型或发到微信的内容无法撤回。

本版使用 AstrBot 4.29 的群名参数解析能力，最低版本要求为 4.29.0。

## 采集规则

- 默认每 60 秒扫描本地服务可见的全部群；可在插件配置中填写 `group_ids` 限定群。每群每轮最多 10 页，每页 100 条；超额留待下一轮，不静默跳过。
- 首次回看最近 24 小时，之后持续增量采集，保存 30 天。安装前更早历史不会自动导入；不能把 `/通知汇总 30` 理解为首次安装即回填 30 天。
- 只认结构化 `atUsernames` 中的 `notify@all`，不因正文包含“@所有人”而误判。
- 为通知关联同发送者、前后 5 分钟内各最多 3 条候选补充。模型只应使用主题相关补充；通知等待至少 60 秒后进入汇总。
- SQLite 数据及进度放在 `data/plugin_data/astrbot_plugin_wechat_notice_digest/notices.db`。扫描期间临时缓存该群扫描窗口内的消息，完成后仅保留最近 15 分钟缓存以关联补充，不长期归档整群聊天。
- 首次绑定一个微信数据库账号；之后不跟随默认账号切换，避免混入其他人的记录。多账号请使用独立实例及数据目录。

## 汇总与隐私

自动采集不调用模型。执行汇总指令时，被选中的通知及候选补充会发送给当前 AstrBot 会话配置的模型服务商。附件只读取接口给出的名称/文字，不下载并分析附件正文。建议选择符合自己数据处理要求的模型服务。

单次默认最多 40 条通知，总输入最多 30000 字符，分批调用模型。单条通知正文最多 2500 字符，单条候选补充最多 1000 字符；任何未纳入或截断均明确提示。模型不可用时显示最近 10 条通知原文，不能将原文回退理解成 AI 总结成功。

同一天正文与候选补充完全一致的通知在分批前合并，保留所有来源编号；不同日期不合并，避免误解“明天”等相对截止时间。不同措辞的相似通知由每批模型尝试合并，跨批语义合并不作保证。

本地 API 地址仅接受回环地址；不接受接口重定向；不读取、不打印数据库解密密钥。持久化文件可能包含私人群通知，应保存在自己的电脑，不要随插件 ZIP 分发。

## 限制和排查

- 本地服务必须提供 `/api/chat/accounts`、`/api/chat/sessions`、`/api/chat/messages`，并返回实时数据来源、消息 ID、发送时间及结构化提及字段。已在本机 WeChatDataAnalysis v2.9.0 + 微信 4.1.15.55 验证读取基础。
- `/通知状态` 不完整、离线、积压或过期时，汇总会提示覆盖限制；接口失败不推进对应群游标。群列表最多 2000 个会话，达到该上限会提示覆盖不完整。
- 电脑未同步记录、已删除消息、历史后补及停机期间不可恢复数据无法保证完整。分页依赖上游消息排序；扫描时删除历史可能影响页位置。
- 微信版本变化及上游工具接口变化可能导致采集失败。窗口长期最小化不影响数据库读取本身，但账号、微信及数据分析工具需保持可用。
- 首版没有开机自启、主动定时推送或任务日历。每次启动 AstrBot 后自动恢复后台采集。

## 每日早报（v1.2.0）

在插件配置开启 `daily_report_enabled`，时间 `daily_report_time` 默认为北京时间 `07:00`，`daily_report_target` 填写私聊 `/sid` 返回的完整 UMO。安装包默认关闭发送、目标留空，不包含个人账号。

早报私聊发送“群名／要做／截止”的简洁条目。首次汇报从计划发送时间前24小时开始，之后保留期内尚未汇报的通知继续等待；没有新增时不发送，屏蔽群不纳入。每次最多采用配置的通知数，未展示通知留待次日。模型不可用时退回本次通知原文。手动汇总不影响早报发送记录。

成功发送全部分段后才记录通知已汇报；分段进度持久保存，失败15分钟后从失败段重试。少数网络超时可能出现服务端已收但未确认的重复段。屏蔽设置改变会取消待发内容；已发送消息无法撤回。用 `/通知状态` 查看下次时间和发送结果。

需要电脑保持开机，AstrBot、微信和本地数据工具持续运行并联网。若已启用后错过时间，恢复运行会补发一次。首次启用或修改目标/时间，会安排下一个未来时刻。个人微信若主动发送会话凭据失效，可先私聊机器人再等待重试。


## 截止时间、紧迫程度与材料（v1.3.0）

手动汇总和每日早报统一排序：今天截止 → 未来三天截止 → 无明确日期但原文明确催办 → 其他明确日期 → 普通无日期 → 已过期事项。各日期档内按截止时间从近到远，同一时刻明确催办者优先。已过期事项单独列在末尾，不代表已经完成或不必补办。

以北京时间判断到期；只有日期没有具体时间时按当天结束判断，相对日期根据通知原始时间推算。无法确定的截止日期保留原话，不强行编造日期。日期和材料由模型提取，重要事项请核对原文。

明确需要准备或提交材料的事项增加“材料：”一行，保留原文份数、格式要求；未提及材料就不增加此行。材料要求不同的事项不会直接合并。未读取附件的内容不会自行推测。
